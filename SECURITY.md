# Security Policy

The Hit maintainers take the integrity and security of source repositories seriously. As a version control tool, maintaining trust and software security is paramount.

---

## Supported Versions

Only the current active release branch receives security updates:

| Version | Supported |
| :--- | :--- |
| 0.1.x | Yes |
| < 0.1.0 | No |

---

## Reporting a Vulnerability

If you discover a security issue or vulnerability in Hit, please do not disclose it publicly or open a public issue.

Report findings privately via:

1. **GitHub Security Advisory**: Submit a draft through [GitHub Security Advisories](https://github.com/hit-scm/hit/security/advisories/new).
2. **Email**: Contact the security team at **security@hit-scm.com**.

### Information to Include

Please provide:
- A description of the vulnerability and its potential impact.
- Step-by-step reproduction instructions or a minimal proof of concept.
- Operating system version, architecture, and `hit --version`.

---

## Response Timeline

- **Initial Acknowledgment**: Within 24 hours of report receipt.
- **Triage and Assessment**: Within 48 hours.
- **Remediation and Advisory**: Coordinated disclosure with reporter attribution prior to public announcement.

Thank you for helping keep Hit and the open-source community secure.
